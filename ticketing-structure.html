Core Domains & Workflows

1. Orders Domain

  • Aggregate Root: Order
  • State: OrderState enum (Pending, Confirmed, Cancelled, Expired)
  • Value Objects: PersonalInfo, OrderItem
  • Workflow: Register → Confirm (Payment) → Issue Tickets → Expire (on timeout)

2. Inventory Domain

  • Aggregates: TicketAvailability, TicketTypeAvailability, PricingPhaseAvailability
  • Purpose: Track available ticket capacity across pricing phases
  • Operations: Create, update capacity, query availability

3. Tickets Domain

  • Aggregate Root: Ticket
  • State: TicketState enum (Issued, Used/Checked-In)
  • Features: QR token generation, check-in pass, visibility control

4. Check-In Domain

  • Operations: Validate QR token, record check-in attempt, manage check-in status
  • Enums: CheckInStatus, CheckInAttemptResult
  • Endpoints: POST check-in with QR code

5. Event Snapshots

  • Purpose: Cache event details for quick reference (published/unpublished state)
  • Sync Points: Triggered by event-service integration events

Integration Points

Incoming Events (Handled)

  • Event.Created → Initialize capacity
  • Event.Published → Activate ticketing
  • Event.Unpublished → Pause ticketing
  • Event.Updated → Sync event details
  • TicketType.Created → Add pricing phase
  • TicketType.Deleted → Clean up capacity
  • TicketCapacity.Added → Update availability
  • Payment.Confirmed → Confirm order & issue tickets
  • Payment.Failed → Cancel order
  • OrderExpiration.Due → Trigger reconciliation job

Background Jobs

  • OrderExpirationReconciliationJob: Reconcile pending orders against timeout
  • OutboxProcessorJob: Process event outbox for reliable publishing
  • Scheduler: Hangfire with PostgreSQL backend
